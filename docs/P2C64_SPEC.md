# P2C-64 確定仕様書（v1.1）
## SYGMA-SCONE 統合アーキテクチャ
— 64パターン平滑化骨格 × 非対称メモリレイアウト（主要14ノード16B統合＋非主要50ノード2B直接参照）× 選択式非線形残差 —

### 1. 設計の6原則（先行検証・マイルストーン1.5で確定済みの前提）
1. **64パターン線形骨格の維持**：パターン数削減（34〜38p）は局所暗記情報で致命的ハンデ（-100 Elo超）を生むため、Egaroucid互換の16種・64インスタンスを一切削らず保持する。
2. **手作業特徴の完全排除**：着手可能数・確定石・パリティ等のビットボード手作業特徴は評価関数から完全排除し、Multi-ProbCut（MPC）との親和性と純スカラー速度を最優先する。
3. **60手番平滑化線形骨格 $W$**：1手刻みの60手番重みを保持する（学習時は隣接手数平滑化正則化を適用）。
4. **絶対色表現・主要14ノードの完全分岐レス $\mathbb{Z}_2$ カノニカル化・テンポ分離**：手番切替コストをゼロ化しつつ、非主要50ノードのキャッシュ密度を最大化する。
5. **非対称メモリレイアウト（Asymmetric Layout）**：非線形残差を持つ主要14ノードのみ16バイト・6手ブロック統合構造体（`BlockEntry16`）へ格納し、非線形データを持たない非主要50ノードは従来の2バイト線形配列（60手番直接参照）へ分離することで、キャッシュ密度と速度を `RAW_NTUPLE_64` に肉薄させる。
6. **Zero-Init Residual学習**：線形骨格 $W$ を収束・固定してから非線形残差を0初期化で学習し、$W$ の共食いを防ぐ（フェーズ2以降の学習パイプラインで使用）。

### 2. 共通骨格仕様（Backbone）

#### 2.1 入力符号化と厳密対称性・テンポ分離
- 各マスの3値符号を **`{白 = 0, 空 = 1, 黒 = 2}`** とする。
- 長さ $n$ のパターンの3進インデックス $x \in [0, 3^n-1]$ に対し、色反転は $\bar{x} = (3^n - 1) - x$ で厳密に与えられる。
- 主要14ノードの **完全分岐レス・乗算ゼロ** の $\mathbb{Z}_2$ カノニカル化と符号反転（$3^n - 1 = 2\cdot\text{half}$ が常に偶数であることを利用）：
  ```cpp
  static inline int32_t neg_mask(int32_t v, int32_t mask) {
      return (v ^ mask) - mask; // mask ∈ {0, -1}
  }
  int32_t d    = META[p].half - x;
  int32_t mask = d >> 31;             // -1 iff x > half, else 0
  int32_t cx   = x + ((d + d) & mask);
  ```
- 非主要50ノードは絶対色3進インデックス `idx[p]` で2バイト配列を直接参照（オフライン対称化により $w(\bar{x}) = -w(x)$ を保証）し、最後に `stm` で一括符号反転する。
- 手番 $\text{stm} \in \{+1\text{ (黒)}, -1\text{ (白)}\}$ に対し、評価値を色反対称成分（盤面優位 $A$）と色対称成分（手番テンポ $T$）へ厳密分解する：
  $$V_{\text{STM}}(B, \text{stm}, t) = \text{stm} \cdot \Big(A_{\text{lin}}(B, t) + A_{\text{res}}(B, b)\Big) + T(B, b)$$
  ここで $t \in \{0,\dots,59\}$ は手数（石数 $- 4$）、$b = t / 6 \in \{0,\dots,9\}$ は6手ブロック番号、$\text{sub} = t \bmod 6$ である。

#### 2.2 パターン構成（16種・64インスタンス）と主要14ノード
- Egaroucid互換の16種・64インスタンス（長さ4〜10マス、全カノニカル状態数 `205,019`、内訳：主要4種カノニカル `45,929`、非主要12種生状態数 `318,168`）を厳密な盤面座標（0..63）と対称展開で定義する。
- **主要14ノード（インデックス `0..13` に配置）**：
  - `0..3`：`Corner 3×3`（NW, NE, SE, SW の時計回り順、各9マス）
  - `4..7`：`Edge+2X`（N, E, S, W の時計回り順、各10マス。各辺 `i` は隅 `i` と隅 `(i+1)&3` を結ぶ）
  - `8..11`：`Line 2`（N, E, S, W の時計回り順、各8マス）
  - `12..13`：`Diag 8`（NW-SE 主対角線 `0`, NE-SW 主対角線 `1`、各8マス）
- **非主要50ノード（インデックス `14..63`）**：残りの12種・50インスタンス。

#### 2.3 非対称メモリレイアウト（総容量 43.51 MiB / 全60手）
1. **主要14ノード用 `BlockEntry16` 配列（7.01 MiB）**：
   - 主要4種（`45,929` カノニカル状態）× 10ブロック × 16バイト ＝ **7.01 MiB**。
   ```cpp
   struct alignas(16) BlockEntry16 {
       int16_t w[6];    // 12B: 6手分の60手番線形骨格 W（色反対称）
       uint8_t aux[4];  //  4B: 主要14ノード専用の非線形残差データ（100%専有）
   };
   static_assert(sizeof(BlockEntry16) == 16 && alignof(BlockEntry16) == 16, "Must be 16B aligned");
   ```
2. **非主要50ノード用 2バイト直接参照配列（36.41 MiB）**：
   - 非主要12種（`318,168` 状態）× 60手番 × `int16_t`（2B）＝ **36.41 MiB**。
   - 従来の `RAW_NTUPLE_64` と同等の最高キャッシュ密度（1キャッシュライン64Bあたり32エントリ）と、カノニカル化演算ゼロの直接参照（`nonkey_w[ply][off + idx[p]]`）を両立する。
3. **超軽量・4隅専用テンポテーブル `corner_tempo`（96.1 KiB / 全60手、9.6 KiB / block）**：
   - `int8_t corner_tempo[10][9842]` として独立配置し、主要14ノードの最初の4回（`Corner 3×3`, `p = 0..3`）で算出済みのカノニカル添字 `cx` をそのまま再利用して4回だけL1常駐参照する。
   - これにより、非主要50ノードの2Bキャッシュ密度を一切損なわず、かつ **`CAND_A`（`aux[4]` を4Bフル消費）を含む全モードで同一のテンポ項 $T(B)$ を欠落なく保持** できる。
- **対称種別ごとの内部対称性制約**：各パターン種別のテーブル焼き込み時、そのパターン固有の内部鏡映（例：`Corner 3×3` の対角鏡映、`Line 2` や `Diag 8` の逆順鏡映、`Center 2×4` の水平・垂直鏡映）に対して線形重み $w$・テンポ $t$・非線形パラメータが厳密に不変（`Edge+2X` の双方向コードのみ `code_fwd(rev(x)) == code_rev(x)`）となるよう構築関数で強制する。

### 3. 選択式非線形残差プラグイン（3候補＋ベースライン）

テンプレート引数 `EvalMode` により、以下の4モード＋素の2B線形ベースラインをゼロオーバーヘッドで切り替え可能に設計する。

#### モード0：`LINEAR_64`（共通非対称骨格のみ）
- $A_{\text{res}} = 0$。また、キャッシュ密度の公平比較用に、全64パターンが「60手番×2B独立配列（＋4隅1Bテンポ）」である `RAW_NTUPLE_64` もベンチマーク専用ベースラインとして用意する。

#### モード1（候補A）：`CAND_A_SCRELU_K2`（Dual-SCReLU $K=2$ ＋ 代数因数分解）
- **`aux[4]` レイアウト**：`int8_t o[2], e[2]`（奇2次元・偶2次元、計4B）。
- **7幾何領域への整数加算（乗算ゼロ）**：
  - 4本の辺ストリップ $r \in \{0..3\}$（グループ0）：`E2X[r] + L2[r] + C3x3[r] + C3x3[(r+1)&3]`
  - 2本の対角ストリップ $r \in \{4, 5\}$（グループ1）：`Diag8[d] + C3x3[d] + C3x3[d+2]`（$d = r - 4$）
  - 1つの全体和 $r = 6$（グループ2）：主要14ノードの総和
  - 各ノードの `o[k]` は `neg_mask(o[k], mask)` で色反転して加算、`e[k]` はそのまま加算。
- **有界活性関数＋代数因数分解（出力ビット完全同値のまま `imul` を 63 → 37 へ41%削減）**：
  $$b_k = \text{clamp}(o_{r,k} + e_{r,k} + \mu_{b,g,k},\, 0,\, Q), \qquad w_k = \text{clamp}(-o_{r,k} + e_{r,k} + \mu_{b,g,k},\, 0,\, Q)$$
  1. **2乗差の因数分解**：$b_k^2 - w_k^2 = (b_k - w_k)(b_k + w_k)$（2 `imul` → 1 `imul`）。
  2. **対称グループ係数 $\beta$ の分配法則くくり出し**：
  $$A_{\text{res}} = \sum_{g=0}^{2} \left[ \beta_{g,0}^{\text{sq}} \sum_{r \in \mathcal{G}_g} (b_{r,0} - w_{r,0})(b_{r,0} + w_{r,0}) + \beta_{g,1}^{\text{sq}} \sum_{r \in \mathcal{G}_g} (b_{r,1} - w_{r,1})(b_{r,1} + w_{r,1}) + \beta_{g}^{\text{pr}} \sum_{r \in \mathcal{G}_g} (b_{r,0} b_{r,1} - w_{r,0} w_{r,1}) \right] \gg S$$
  - 右シフトは0方向丸め `sym_rshift(x, S) = (x + ((x >> 31) & ((1 << S) - 1))) >> S` を用い、負数での1LSB対称性破れを厳密に防ぐ。

#### モード2（候補B）：`CAND_B_SCONED_3W3B`（SCONE-D 3way-3bit・乗算ゼロ）
- **`aux[4]` レイアウト**：`uint8_t code_fwd, code_rev`（下位3bit使用：`0..7`、残り2B空き）。
- **色反転対合（自己双対不動点付き対合 $\iota_3$）**：
  - 鏡映と色反転が一致する反鏡映状態（例：`rev(x) == x̄` となる `(B,B,B,B,W,W,W,W)` 等の盤面）でも全16変換の bit-exact 対称性を保つため、3bit記号空間 `{0..7}` 上の色反転対合は **3組の色双対ペア `{0↔1, 2↔3, 4↔5}` ＋ 2個の自己双対中立コード `{6↔6, 7↔7}`** として定義する（分岐レス2命令：`z ^ (mask & ((~((z >> 1) & (z >> 2))) & 1))`）。
  - 単一コード型の鏡映不変パターン（`C3x3`, `L2`, `Diag8`）で `rev(x) == x̄` となる状態は必ず自己双対コード `{6, 7}` へ割り当てることで、数学的矛盾なく全16変換で厳密一致する。
- **1段・10回のL1常駐マクロLUT参照（3テーブル × 512エントリ × `int16_t` ＝ 計 3.0 KiB / block）**：
  - 9ビット連結キー `k = (z0 << 6) | (z1 << 3) | z2` で直接参照する（オフライン焼き込み時に `T[ι(z0), ι(z1), ι(z2)] == -T[z0, z1, z2]` を強制。これにより実行時のキーカノニカル化と `neg_if` が不要となり、1.5 KiB圧縮版より命令数も削減される）。
  1. `T_CW` ×4（隅＋隣接2辺・19マス）：`(C3x3[i], E2X[i].fwd, E2X[(i+3)&3].rev)`
     - 対称化条件：`C3x3` のコードは対角鏡映不変（`code(x) == code(x^T)`）、テーブル焼き込み時に `T_CW[c, e1, e2] == T_CW[c, e2, e1]`。
  2. `T_EA` ×4（辺の両端構造＋中辺・16マス）：`(E2X[i].fwd, E2X[i].rev, L2[i])`
     - 対称化条件：`L2` のコードは左右鏡映不変（`code(x) == code(rev(x))`）、`E2X` は `code_fwd(rev(x)) == code_rev(x)`、テーブル焼き込み時に `T_EA[e1, e2, l2] == T_EA[e2, e1, l2]`。
     - ※これにより主要14ノード構成・4参照のまま、左右鏡映を含む全16変換で完全 bit-exact 対称となる。
  3. `T_CD` ×2（主対角線＋対向両隅・22マス）：`(C3x3[d], Diag8[d], C3x3[d+2])`
     - 対称化条件：`Diag8` のコードは逆順不変（`code(x) == code(rev(x))`）、テーブル焼き込み時に `T_CD[a, d, b] == T_CD[b, d, a]`。
- **`Key-14 First` スケジューリング**：必ず最初に `p = 0..13` を読み込み、直後に10回のマクロLUT参照を発行してから、残り `p = 14..63` の2B直接参照線形加算を実行することで、ポインタチェイシング遅延を隠蔽する。カーネル全体の整数乗算（`imul`）は厳密に **0命令** とする。
- **MPC安全焼き込み式（フェーズ2学習パイプライン用仕様）**：
  $$T_{\text{baked}}[k] = \text{clip}\!\left(\frac{\sum_{n \in k} s_n r_n}{n_k + \lambda_{\text{EB}}},\; -A_{\max},\; +A_{\max}\right)$$
  （億局面規模の目安：$\lambda_{\text{EB}} \in [200, 500],\; A_{\max} \in [2.5, 3.5]$ 石相当）

#### モード3（候補C）：`CAND_C_HYBRID`（16B厳密パック融合：Dual-SCReLU $K=1$ ＋ SCONE-D 3way-3bit）
- **`aux[4]` レイアウト**：
  - `aux[0]`：`int8_t o0`（奇1次元）
  - `aux[1]`：`int8_t e0`（偶1次元）
  - `aux[2]`：`uint8_t codes`（下位3bit `code_fwd` | 上位3bit `code_rev`）
  - `aux[3]`：`uint8_t reserved`（将来拡張用の空き1B）
- **推論**：代数因数分解版のモード1（$K=1$、ペア積なし：`imul` 18 → **10命令**）と、モード2の10回3way-3bitマクロLUT（`Key-14 First` 配置）を合算して $A_{\text{res}}$ とする。
