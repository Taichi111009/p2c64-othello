## エグゼクティブ・サマリー（結論・Go/No-Go 判定・最優先ロードマップ）

### 結論（Conclusion First）

**問い：「純スカラー 0-SIMD・完全公平対局で `+45 〜 +70 Elo` 帯へ抜ける現実的な打開策は存在するか？」**

**答え：存在する（明確な Go）。ただし、現行の「凍結 Tier-1 ＋ 5% 遅延ゲート Stage 3 ＋ 終局石差 L2（$\lambda=0$）」パラダイムの延長上には存在しない。**

実測因果分離実験（`/tmp/p2c64_exp_{a,b,c}/`）および独立追試（`exp5_ondemand_swarpack`）により、従来の仮説を覆す **3 つの決定的な物理的事実** が判明した。

1. **Stage 3（`633.8 ns`）の正体はメモリアクセスではなく `89.2%` が純スカラー計算**であり、24 埋め込み＋24 Tier-1 ロードは **わずか `10.8%`（`68.7 ns`）** に過ぎない。内訳は `32→16→1` MLP（544 乗算）が `40.2%`（`256.2 ns`）、追加特徴が `24.6%`（うち `ply >= 24` の 4 近傍空領域 flood-fill 単体で `103.3 ns = 16.3%`）、44 項 Pairwise SCReLU が `24.4%`（`155.3 ns`）である。さらに決定的な発見として、**64-bit SWAR パック（`int16x4`）のデータ配置自体は劇的に有効（112 回の `int8` スカラー展開を撤去）だが、着手ごとの差分更新（Incremental `make_move`）は 100% 葉でも「葉都度ロード SWAR-Packed（1-sub PTM）」に `-1.8%〜-3.7%` NPS で完全劣後する**ことが実証された（`exp5`）。**葉都度ロード SWAR-Packed** を採用すれば、着手差分・パス偶奇状態（約 300 LOC）を完全撤去しつつ **フル 30 ブロック EO パリティを維持したまま 100% 葉評価が Haswell `-10.15%`（4ch）/ `-14.01%`（8ch）** と現行 `WACA_V33`（`-15.31%`）を上回る速度で動作する。
2. **中盤 `d4→d8`（`ply 30–39`）の MPC $\sigma$ 悪化（`+0.198 石`: `RAW 2.516 → v3.3 2.714`）は、ゲート不連続ではなく `87.0%`（`+0.172 石`）が「終局石差 L2 学習による非ゲート静的学習分散」** である（100% 非ゲート `GateMode::FULL` でも `2.6880` に悪化；独立 `N=200` 標本でも `67.8%` 非ゲート支配が再現；なお `ply 40–49` の `82.1%` ゲート寄与は `N=399` の標本分散が大きく独立 `N=200` では不安定）。さらに 52,631 局面の 1-ply Bellman 整合性検証により、`Egaroucid_Train_Data.zip` が Lv.17 探索スコアを用いる `ply 0–9` ではバイアス縮小により `V3 FULL` の生 RMSE が `RAW` を下回る（`2.514` vs `2.546`、ただし脱バイアス Std は `ply 6–10` で依然 `+0.07〜+0.18` 悪化）一方、終局石差に切り替わる **`ply 11 → 12` 境界を経て `ply 30–49` で脱バイアス Std が `+0.31〜+0.44`（最大 `ply 46` RMSE `+0.562`）へ爆発** することが確認された。つまり **軸 A（脱ゲーティング：ゲート漏れ `43.5–45.0%`・`d3→d7` 83% 消失・`S3%` 罠の根絶）と軸 B（探索整合ターゲット）は代替ではなく相互必須** である。
3. **現行ゲート型 `WACA_V33` に強力な公平探索圧縮（Egaroucid `d/2` MPC・複数ペア MPC・Aspiration・LMR）を入れると、二重の逆転現象（`d-2` ペアでの `RAW` 優先圧縮 ＋ `WACA` の `S3%` インフレーション `+35〜+56%`）により `WACA` が逆に弱くなる**。しかし **軸 A（100% 葉 On-Demand SWAR-Packed `int16x4` 統合評価：Haswell `-9.0%〜-14.0%`、Colab 換算 `~6〜10%`）** で `S3%` 罠を消滅させ、**軸 B（既存 2,551 万局面の `ply 12..49` を固定深さ `d6/d8` 再ラベル `λ=0.5–0.75` ＋ 凍結 Tier-1 解除）** で `d4→d8` $\sigma$ を `RAW` 以下に逆転させた瞬間に、**軸 C（`d_idx<=4` クランプ修正 + 校正 `t=1.25–1.30` + パリティ一致 `d/2` MPC + 評価マージン連動 LMR `D3_mgLMR_m4`）** が `WACA` 優位の追い風（`+8〜+14 Elo`）へと反転する。

- **単純ロード回数式の落とし穴（第 2.4 節の実測で覆った重要知見）**: ロード回数のみを数えると、起動率 $f$・パターン数 $K$ の都度ロードは $f \cdot K$ 回、差分更新は $2 u r$ 回となるため、30%-Leaf K14+C10（$7.2 \ll 20.3$）では On-Demand の圧勝が即座に分かる一方、100%-Leaf Key-14（$2 u r = 10.1 < 14$）では一見すると差分更新が有利に見える。しかし実際には、差分更新（Dual-PTM）には **(i) 全内部＋葉着手（`1.354×`）での `dirty_k14(sq, fl)` ビットマスク展開ループ、(ii) 毎手の 48B `SwarAccState` コピーメイク、(iii) 黒白 2 視点同時更新による 2 倍の ALU 演算（葉あたり `40` vs `28` 本の `uint64_t` 加減算）、(iv) ブロックあたり 2 倍のキャッシュ専有（32B `DualEmb8` vs 16B `SingleSwarEmb8`）** が掛かる。結果として第 2.4 節の厳密対照実測（`exp5`）では、**同じ 64-bit SWAR パック（`int16x4`）を用いた場合、100%-Leaf でも「葉都度ロード SWAR-Packed（1-sub PTM）」が着手差分更新 SWAR を全構成で `+1.8%〜+3.7%` NPS 上回る**ことが実証された。

### 2.2 STM 視点反転（Color-Even `52.1%`）と `int16x4` SWAR パックのビット完全検証

`/tmp/p2c64_exp_a/exp3_swar_prototypes.cpp` および `exp5_ondemand_swarpack.cpp` で実重み `waca_g2_v33.p2c` を解析し、純スカラー 64-bit SWAR カーネルを実装・検証した。

1. **STM 視点反転の落とし穴と 1-sub PTM（On-Demand）vs Dual-PTM（差分更新）の決定的差**:
   - 実 `waca_g2_v33.p2c` の埋め込み $h(x)$ を色偶対称成分 $\frac{1}{2}(h(x)+h(\bar{x}))$ と色奇対称成分 $\frac{1}{2}(h(x)-h(\bar{x}))$ に分解すると、Key-14 `h_emb`・Center-10 `ctr_emb` ともに全チャネルで **`52.1%` Color-Even / `47.9%` Color-Odd** であった。したがって素朴な色反対称仮定 $h(\bar{x}) = -h(x)$（1-`SUB` 反転）は学習済み Full-PTM 信号エネルギーの半分以上を破壊する。
   - **差分更新方式**では黒白両視点の維持に Co-located Dual-PTM（`DualEmb4`: 16B / `DualEmb8`: 32B）が必要となりテーブル容量と ALU 演算が **2 倍化** する。一方、**葉都度ロード SWAR-Packed（`SingleSwarEmb4`: 8B / `SingleSwarEmb8`: 16B）** では現行 Tier-1 と全く同じ **`1-sub` PTM インデックス（白番時 `raw_off_end - idx[p]`）** をそのまま使えるため、**1× テーブル容量・1× ALU・ゼロ `make_move` 状態** で 100% Full-PTM を完全保存できる。
2. **オフセット符号化 `int16x4`（`C = 2048`）による 0 マスク 4 レーン並列加算と bit-63 対応 SWAR ReLU**:
   - 各重み $w_i \in [-2048, +2047]$ を非負オフセット $u_i = w_i + 2048 \in [0, 4095]$ で 64-bit ワードへ 4 レーン詰め（`pack_u16x4`）、Key-14（$K=14$）初期値を `0x0800080008000800ULL`（安全床 $+2048$）とする。各レーン和は $[2048, 59378]$ に収まり、14 パターンの加算（または差分更新の中間値 $59378 + 4095 = \mathbf{63,473 < 65,536}$）で **桁あふれ・ボロー混線が数理的にゼロ**（Hacker's Delight 流の 6–7 命令マスクを完全撤去し、4 チャネルあたり **1-`ADD`** で集計完了）。
   - 葉での非バイアス化＋分岐なし 4 レーン同時 ReLU は、最上位ビット 63（レーン 3 負値）でも壊れない 11 命令（`objdump` 上 `swar_unbias_relu_i16x4` 15 命令 / `0 imul`, 実測 `~2.3 ns` / 4 レーン）で実装できる：
     ```cpp
     uint64_t x = (acc + u_mu) ^ 0x8000800080008000ULL; // 1-XOR carry-free unbias
     uint64_t s = x & 0x8000800080008000ULL;            // sign bits of 4 lanes
     uint64_t m = (s - (s >> 15)) | s;                  // exact 0xFFFF even for bit 63!
     uint64_t y = x & ~m;                               // 4-lane SWAR ReLU
     ```
   - **ビット完全検証**: `exp3` の 220 完全対局（13,200 手, 123 パス）＋極値 10,000 回テストに加え、独立 UBSan 敵対ファザー（390,625 通り網羅＋bit-63 境界 6,561 通り＋20 万ステップ＋パス多発 500 対局 29,543 手）および `exp5` の `val.bin` 20,000 局面 × 黒白両視点（**40,000 評価**）すべてでスカラー参照値に対し **`0` エラー** を確認済み。
   - *(`int32_t` 乗算ヘッドルーム留意点：`readout_swar_relu_dot8/16` のように非クランプ ReLU 出力を直接 `int16_t` 重みと内積する場合、現行 `v3.3` 重み規模（$|h| \le 87$）では `int32_t` で余裕だが、将来 12-bit 全域 `[-2048, +2047]` を使う本番実装では必ず ReLU 出力を `SCRELU_Q` へクランプするか `int64_t` で累積すること。)*
3. **`int8x8` の物理的不成立（Design `A4` 定量証明）**:
   - `K = 14` を 8-bit レーン（上限 `255`）で安全に集計するには $w_i \in [-8, +8]$（4.09 bit；減算先行でも $[-9, +9]$, 4.25 bit）しか使えない。実 `waca_g2_v33.p2c` の `h_emb`（$\max|h|=87$）を非クリップで詰めると **9,020 / 9,020 中盤局面（`100.00%`）でレーン間キャリー破壊** が発生し、安全域 `[-9, +9]` へ再量子化しても `val.bin` 10,000 局面でグローバル Key-14 和（RMS `56.50`）に対し **RMSE `10.99`（`19.5%` の相対歪み）** を生じる（`int16x4` は `0.00 = 0.0%` 完全可逆かつ 16 倍の動的レンジ余裕）。よって **`int8x8` は明確に棄却**。

### 2.3 SCReLU/Pairwise の 64-bit `IMUL` 限界と 30-block EO-Parity の劇的解放

- **64-bit `IMUL` でのレーン並列二乗/ペア乗算の数学的不可能性**（SAMD `arXiv:1809.10572`, `uops.info`）: 64-bit 整数乗算 `IMUL` はレーン間畳み込み項（$a_0 b_1 + a_1 b_0$ 等）を生成するため、SCReLU（$u^2$）や Pairwise 乗算（$u_k \cdot v_k$）は SWAR レーン並列実行が不可能である。したがって葉では (i) SWAR ReLU（`~2.3 ns`/4ch）＋スカラー `8→1` ドット（8 `imul`）、または (ii) 8 レーンをスカラー `int32_t` 展開して 12 項 Pairwise/SCReLU（24 `imul`）を実行するのが 0-SIMD での物理的最適解である（Skylake–Zen 4 の `IMUL` スループット `1/cycle` に適合）。
- **「葉都度ロード SWAR-Packed」による 30-block EO-Parity の完全解放**: 差分更新方式では 30 ブロック偶奇分離（`PLY_TO_EO30_BLK`）が 4 手ごとのブロック境界リフレッシュで破綻した（`A2b`: `73.33 ns/move = 101.93 ns/leaf` で棄却）ため、1-block や 2-block への容量妥協を強いられていた。しかし **葉都度ロード SWAR-Packed（`ondem_swar4` 21 命令 / `ondem_swar8` 23–26 命令, `0 imul, 0 SIMD, 0 PLT`）は葉でのみテーブルを読むためブロック境界リフレッシュが一切ゼロ** であり、**フル 30 ブロック EO パリティ（`S4` 4ch `21.0 MiB` / `S8` 8ch `42.0 MiB`）をそのまま 100% 葉で高速実行できる**。
- **L3 キャッシュ容量に関するハードウェア留意点**: 本測定機（Haswell, L3 `45 MiB`）では 8ch 30-blk EO（`42.0 MiB`）が L3 内にほぼ収まり `-14.01%` を達成する。**L3 が `16–24 MiB` の CPU では `42.0 MiB` で L3 ミスが増え得るため、2-blk EO 8ch（`2.80 MiB`, `S7 -12.09%`）または 4ch 30-blk EO（`21.0 MiB`, `S4 -10.15%`）を選択** する設計が安全である。

### 2.5 `r_key_screlu` vs `r_mlp` 共適応の正確な解釈と Path A-I vs Path A-II 選択基準

`/tmp/p2c64_exp_b/exp2_component_ablation` で現行 `waca_g2_v33.p2c` を未見 127.58 万局面でコンポーネント分解した際、一見不可解な数値が出た：`V1 + r_key_screlu` 単体の RMSE は `5.9319`（`V1` `5.8547` より悪化）、「`V1 + r_mlp` 単体」も `5.7658` に留まるのに対し、合算 `V3` は **`5.4494`（`-0.4053`）** を達成する。原因は **強い負相関による共適応（`Corr(r_key_screlu, r_mlp) = -0.4871`, 中盤 `ply 20–39` で `-0.537`）** と **`r_key_screlu` に定数バイアス項 `b_screlu` が欠落していた構造** にある（`mean(r_key) = +0.3235` を `mean(r_mlp) = -0.3233` が打ち消し、`Corr(V1, r_key) = -0.2803` を `Corr(V1, r_mlp) = +0.3371` が打ち消していた）。実際、生振幅では **`r_key_screlu`（`std = 2.0926`, `p95 = 4.328`）が 544 乗算の `r_mlp`（`std = 1.7875`, `p95 = 3.680`）を上回っている**。

この知見と `exp5` の実証結果から、軸 A の 2 つのパスを以下のように刷新・位置づける：

1. **Path A-I（主力 P0：100%-Leaf 統合 `On-Demand SWAR-Packed int16x4`［1-sub PTM, フル 30-blk EO または 2-blk EO］＋ **`b_ply`**）**:
   - **強み**: ゲート不連続・`tt_guard` 損失・軸 C の `S3%` インフレーション罠を **完全にゼロ化** しつつ、着手差分・パス偶奇状態（約 300 LOC）も不要。**フル 30 ブロック EO パリティを保持したまま `S4 (-10.15%)` / `S8 (-14.01%)` で現行 `WACA_V33`（`-15.31%`）を上回る速度** を達成する（L3 16–24 MiB CPU では `S7` 2-blk EO `2.8 MiB`, `-12.09%` または `S4` 4ch 30-blk `21.0 MiB` を選択）。Stockfish 19 PR #6796 と完全に整合する構造的王道。
   - **留意点**: 集計は Key-14 のグローバル和（$\sum_{p=0}^{13} h_p$）であり、現行 `v3.3` の 4 辺・2 対角の局所グループ（`he[0..13]` 個別参照）や Center-10 は省く。ただし 30 ブロック EO を維持できるため 1-block 差分案より表現力は大幅に高く、**必ず `b_ply`（手番別切片）を付与して軸 B の凍結 Tier-1 解除＋再ラベルデータで共同再学習** し、厳格化した Gate 1（`-ΔRMSE ≥ 0.40` @ `tax ≤ 15%` / `≥ 0.44` @ `tax ≤ 18%` ＋ 20k 固定ノード `≥ +40 Elo`）で検証する。
2. **Path A-II（高精度フォールバック P1：高頻度ゲート `TRUE D11`［30-blk EO `23.3 MiB`, flood-fill 撤去］）**:
   - **正確な実測コスト**: `exp4` の `-15.48%`（再計測 `-18.6%〜-21.9%`）は 1-block `3.1 MiB` グローバル `PW8 + 16→8→1` プロキシであり、**真の 30 ブロック EO（`23.3 MiB`）** では `S9`（global `PW8 + 16→8→1`, 30.3% 起動）が **Haswell `-20.22%`**（独立追試 `-19.42%`、Colab 推定 `~13–15%`）、**44 項局所 `he[0..13]` SCReLU ＋ `16→8→1`**（`S10`, 30.3% 起動）は **Haswell `-24.37%`**（独立追試 `-23.94%`、Colab 推定 `~17–19%`）を要する。それでも 30% ゲート差分 SWAR（`S11 -28.04%`）は大きく上回る。
   - **運用方針**: もし Gate 1 で Path A-I が表現力不足に終わった場合に切り替える。局所 44 項 `he[0..13]` を Haswell `~15–18%` 税（Colab `~11–13%`）内に収めるには、**`16→8→1` MLP を撤去して 44 項局所 SCReLU 単体とするか、起動率を `30% → 15–20%` へ調整** する。

### 3.1 凍結 Tier-1 解除 ＋ `|R3 - R1|` 分散ペナルティの定量検証

「Tier-1 を解凍して `|R3 - R1|` の分散ペナルティを入れれば、Stage 3 の情報を Tier-1 に吸収させてゲート漏れを減らせるのでは？」という仮説を、`/tmp/p2c64_exp_b/exp2_component_ablation` にて厳格な 50/50 標本外（OOS: 63.8 万学習 / 63.8 万検証）射影で直接検証した。

- **統合 100%-Leaf モデルおよび探索再ラベル学習では必須かつ低コスト（P0）**: 学習ターゲットを終局石差（$\lambda=0$）から `d6/d8` 探索スコア（$\lambda=0.5\text{–}0.75$）へ変更する際、Tier-1 自身（24.6M FP32 パラメータ）を解凍して再適応させる必要がある。追加 VRAM はわずか **`~375 MiB`**（重み `93.85 MiB` + AdamW `m,v` `281.5 MiB`）、Colab A100 でのステップ増は `<20%`（9 エポック計 **`~20–30 分`**）と極めて軽量である。

### 3.2 Egaroucid 型「合法手ビット組み込みパターン」Tier-1 統合の評価：明確な No-Go

- **一次ソース検証（`Nyanyan/Egaroucid` tag `v6.5.2` vs 7.x）**: Egaroucid 6.5.2 は 8 行＋8 列の `(opp_mob, pl_mob)` を参照する `eval_mobility_pattern[60][4][256][256]`（**30 MiB**, 16 ランダム参照）および `canput`/`surround` 2D テーブルを実装していたが、**Egaroucid 7.x で 3 つすべてを公式削除** した。作者（Nyanyan）は「葉でのビットボード合法手再計算とキャッシュミスによる速度低下が大きいため削除し、学習データの改善によって同等以上の棋力を達成した」と明記している。
- **P2C-64 での実測裏付け**: P2C-64 の Stage 2.5（機動性＋角/X 機動性＋多項式）は全葉実行すれば `76.9 ns/call`（`RAW` `78.5 ns` とほぼ同等の速度コストで `-25〜-30%` NPS 増）を要する割に RMSE 改善は **`-0.0634`**（`V3` のわずか `15.6%`）に留まり、しかも第 1.4 節の通り **`Stage 2.5 Only` 単体で `d4→d8` `ply 30–39` $\sigma$ を `+0.0513` 悪化** させている。純スカラー 0-SIMD 制約下で 30 MiB 合法手パターンを Tier-1 に統合するのは **明確な No-Go** である。

### 4.2 重大発見 2：`v3.4` 校正 MPC (`-9.27 Elo`) と `d_idx <= 4` クランプバグの完全解明

1. **`v3.4` で校正 MPC が `RAW` 自身を `-9.27 ± 17.08 Elo` 弱体化させた理由**:
   - `include/p2c64_search.hpp:366-371` の Legacy 線形近似式 $\sigma_{\text{leg}}(d_{\text{sh}}, \text{ply})$ と実測校正値 $\sigma_{\text{cal}}$ を比較すると、Legacy は `ply 10..29` で過保守（$t_{\text{eff}} = 1.52\text{–}1.70$）だった一方、**重要かつ計算量の大きい `ply 40..59` では実測より 12–27% 小さい $\sigma$ を与えており、実質 `t_eff = 1.25–1.35` の攻撃的スケジュールで動いていた**（`d1→d5` `40..49`: `1.247`, `d3→d7`: `1.248`, `d4→d8`: `1.263`, `50..59`: `1.097`）。これを一律 `cal t = 1.50` へ切り替えたため、中終盤のカット率が `66.90% → 64.60%` へ低下し `-9.27 Elo` を失った。さらに `d4→d8` `ply 30..39` では Legacy が偶然 `RAW` を `t_eff = 1.640`、`v3.3` を `t_eff = 1.520` と `v3.3` 有利に枝刈りしていたため、校正で均等化した際に `v3.3 vs RAW` も `+29.95 → +26.46`（`-3.49 Elo`）落ちた。
2. **`p2c64_search.hpp:594` の `d_idx <= 4` クランプバグ**:
   - 現行コードは `d_idx = clamp(d_sh, 1, 4) - 1` とハードクランプしており、50–100ms で頻出する `depth = 9, 10`（`d5→d9`, `d6→d10`）でも **`d4→d8` の大きな $\sigma$ テーブルを流用** していた。同一局面ペア測定の結果、`d5→d9`（`N=192`）で実質 `t_eff` を **`1.684` (`RAW`) / `1.717` (`GATED`) / `1.736` (`FULL`)**、`d6→d10`（`N=64`）でも **`1.656` (`RAW`) / `1.673` (`GATED`) / `1.652` (`FULL`)** へ過締めし、特に **`ply 30..39` では `GATED` `t_eff = 1.851` vs `RAW` `1.732`** と `WACA` 側をより強く不利にしていた（50–100ms での Elo 減衰の一因）。
3. **奇偶不一致ペアのパリティバイアス**: `d3→d6`（`-2.170 石`）、`d5→d10`（`-2.004 石`）のように浅深の偶奇が不一致だと約 2 石の系統バイアスが生じる。Egaroucid の `((d/2) & ~1) + (d & 1)` がパリティ一致を厳守する数理的必然性が確認された。

### 4.3 オセロ盤面石差スイング実測と探索施策の採否判定

   - **Kill 基準**: `RAW (2.516)` を下回らない場合 → `V33 d6` 教師が弱すぎるため `d8` 再ラベル（`46.4 CPU-h ≈ ~3.5h`）または外部 Egaroucid 強教師再ラベルへ切替。それでも改善しなければ総括へ移行。

   - **実施**: **`On-Demand SWAR-Packed int16x4`（Key-14 8ch, 1-sub PTM, フル 30-blk EO `42.0 MiB`［L3 16–24 MiB 環境では 2-blk EO `2.8 MiB` または 4ch 30-blk EO `21.0 MiB`］＋ 手番別 Pairwise SCReLU ＋ `b_ply`）** を **凍結 Tier-1 解除** で Gate 0 の再ラベルデータ上にて End-to-End 共同学習（+ オプションで 20% サブサンプル 1-ply Bellman 損失）。`audit_asm.sh` 相当で `xmm/ymm/zmm=0, plt=0` を検証し、20ms 実戦 NPS 税および 20k 固定ノード対局を測定。
   - **Pass 基準（感度モデルと数理整合するよう厳格化）**:
     1. 精度：**`val.bin`（$\lambda=0$）およびホールドアウト `d6/d8` 再ラベル Val の双方** で評価し（$\lambda=0.65$ 学習による終局石差 `val.bin` 側のターゲットシフト見かけ悪化での誤 Kill を防止）、探索整合実効 **`-ΔRMSE ≥ 0.40`（`tax ≤ 15%` 時）または `≥ 0.44`（`tax ≤ 18%` 時）** を達成すること。
     2. 固定ノード棋力：20k 固定ノード対局（対 `RAW_NTUPLE_64`）で **`≥ +40 Elo`**。
     3. 探索整合性：`d4→d8` `ply 30–39` $\sigma \le 2.48$。
   - **Kill / Fallback 基準**: 上記を満たさない場合（グローバル Key-14 のみでは表現力不足）→ **Path A-II（`TRUE D11` 30-blk EO `23.3 MiB`, flood-fill 撤去；global `PW8+16→8→1`［Haswell `-20.2%`］または 44 項局所 `he[0..13]` 単体［`16→8→1` MLP 撤去または起動率 `15–20%` 調整により Haswell `~15–18%` 予算内へ収める］）** へ切り替え、再評価する。
3. **Gate 2（所要 ~2 時間・2,000 局完全公平対局）— 軸 C 公平探索統合と `+45〜+70 Elo` 検証**:
   - **実施**: `d_idx <= 4` クランプ修正 + 校正 MPC `t=1.25–1.30` + 終盤動的 `t` + パリティ一致 `d/2` MPC + `D3_mgLMR_m4` を **`RAW_NTUPLE_64` と新 P2C-64 の双方へ 100% 公平適用** し、20ms / 50ms / 100ms で計 2,000 局以上対戦（推奨副次対照：同一 `d6/d8` 再ラベル学習済み `RAW_NTUPLE_64` 戦も併走し、データ利得とモデル利得を分離記録）。
   - **Pass 基準**: 対 `RAW_NTUPLE_64` 統合 Elo **`≥ +45 Elo`**（95% CI 下限 `> +38`）かつ 50–100ms での減衰解消。
   - **Kill / 総括基準**: 20–100ms 統合 Elo が `+45 Elo` 未満で `d4→d8` $\sigma$ 改善も頭打ちなら、純スカラー 0-SIMD・単一スレッド・2,551 万盤面制約下での実用上限到達としてプロジェクトを堂々と総括する。
4. **Gate 3（任意・`+60〜+70 Elo` 狙いの拡張）**:
   - Gate 2 で `+45〜+55 Elo` を達成した場合、`V33 GATED d8 MPC`（`~3.5h`）再ラベルへの昇格、または `On-Demand SWAR-Packed 4ch 30-blk EO`（Haswell `-10.15%` 税）との速度-精度パレート探索により `+60〜+70 Elo` 帯を狙う。

### 5.4 正直な撤退判断（既存 2,551 万データ再ラベル一切不可の厳密制約下）

もし研究条件として「既存 2,551 万局面のターゲット値（`train.bin` のスコア列）の書き換え・再ラベルを一切認めない」という厳密制約が課される場合、Scenario 2 の物理的限界（期待 `+40.9 Elo`、`+45 Elo` には `-ΔRMSE=0.44` 時 `tax ≤ 11.1%` / `0.45` 時 `≤ 12.0%`、`+55 Elo` には `≤ 4.5%` が必要、`+70 Elo` は物理的不可能）が直接効いてくる。この場合、`+45〜+70 Elo` 帯の安定突破は **No-Go** であり、オフライン 1-ply Bellman ＋ `On-Demand SWAR-Packed 4ch 30-blk EO` による `+38〜+43 Elo` 確認をもって（あるいは現行 `+28.47 ± 4.51 Elo` を純スカラー 0-SIMD カスケード評価の完成形として）**総括することが最も合理的かつ誠実な工学判断** である。

### 6.4 限界・留意事項（Caveats & Limitations）

1. **ローカル検証機（Haswell 2.30 GHz, L3 45 MiB）と他 CPU 環境の差**: ローカル KVM VM では `RAW` が `78.5–87.0 ns`（`3,790–3,886 kNPS`）、`WACA_V33` の NPS 税が `-14.8%〜-15.3%` となり、高速 Colab Xeon（`~63 ns`, `5,900–7,000 kNPS`, NPS 税 `-9.8%〜-11.5%`）より相対税率が厳しめに出る（安全側の保守的見積り）。一方、`S8`（8ch 30-blk EO, `42.0 MiB`）は Haswell の 45 MiB L3 に収まるため好成績だが、**L3 が `16–24 MiB` の CPU では 2-blk EO 8ch（`2.80 MiB`, `S7 -12.09%`）または 4ch 30-blk EO（`21.0 MiB`, `S4 -10.15%`）を選ぶべき** である。
2. **GPU 未搭載環境による未再学習モデルの精度留保**: ローカル環境に GPU/PyTorch が存在しないため、刷新した Path A-I（`On-Demand SWAR-Packed int16x4` 30-blk EO Key-14 8ch + `b_ply`）および Path A-II（`TRUE D11`）の最終 Val RMSE は未実測である。現行 `v3.3` の `r_key_screlu` vs `r_mlp` 分解は共適応（`Corr = -0.4871`）下の事後アブレーションであるため、真の単独精度は Gate 1（Colab A100）で `val.bin` と再ラベル Val の双方＋20k 固定ノード対局によって必ず実測検証する必要がある。
3. **WLS 速度交換レートの 95% 信頼区間幅**: `β_nps = +85.1 ± 60.5 Elo / 2× NPS` は個別 1,000 局対局の統計分散（`±14–17 Elo`）により幅が広い。独立 LOO ジャックナイフ（`[+74.2, +95.4]`）で中央推定の安定性を確認した上で、全シナリオの Worst/Expected/Best に `β_nps ∈ [70, 105]`・`α_acc ∈ [105, 145]` を明示的に伝播させて過信を排した。
4. **標本分散および序盤・中盤の分布交絡**: `N=2,000` MPC 校正における端バケット（`ply 0..9` `N=40`, `ply 50..59` `N=79`）・`d=10`（`N=64`）・および `ply 40..49` のゲート寄与比 `82.1%`（`G−F=+0.069` vs `SE ≈ 0.13`、独立 `N=200` では再現せず）は標本分散が大きい。また第 1.5 節の `ply 0..11` vs `ply 12..59` 比較には「全列挙序盤木（`val.bin` 平均 `+7.06`）」対「ランダム序盤自己対戦」の分布交絡が含まれるため、探索整合ターゲットの因果効果は必ず Gate 0 の実 `d4→d8` $\sigma$ 測定で直接確定させる設計とした。
5. **自己再ラベルの教師バイアス上限**: `V33 d6/d8` は元の終局ラベル生成元（Egaroucid 7.5.1 Lv.17）より弱いため、`λ = 1.0` での完全自己蒸留は推奨せず、終局石差とのブレンド **`λ = 0.50–0.75`** を標準設計とした。
